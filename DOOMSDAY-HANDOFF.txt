1. ORIGINAL TASK
================

Implement the complete cross-viewport ECRATS update in DOOMSDAY-INPUT.txt while preserving
private data and history, enforcing authorization server-side, using safe forward migrations,
adding focused tests, validating responsive behavior, and updating documentation.

The required business changes are:

- Treat Full Board, Expedited, and Exempted as application classifications, never Reviewer
  classifications. Adviser is the primary role and Reviewer is an RES-controlled capability.
- Add Reviewer capability/capacity to individual Adviser creation and Adviser Excel import.
- Revise the RES Decision & Certificates queue, modal, Full Board conflict behavior, and
  application-level decision release. Approved consensus must automatically enter secure
  certificate preparation without a separate decision-release action.

  and generate one personalized certificate per applicant-supplied recipient name.
- Replace Review Monitoring cards with reviewer/adviser tables, filters, and secure drill-downs.
- Make initial and revision document selection upload automatically without Upload/Upload All.
- Redesign Revision and Certificates status, navigation, three-step progress, feedback/version
  panels, collapsible sections, and released worksheet access.
- Prevent Minor/Major Revision decisions without at least one actionable revision comment.

  access to the Reviewer's own prior comments.

2.6 Document business versions
------------------------------

- Replacing a file during initial submission retains Version 1.
- Revision upload now increments from the maximum actual document version only on the first
  replacement of that requirement in that revision cycle.
- Re-uploading before revision submission retains the same business version.
- A document first replaced during the second revision cycle becomes Version 2, not Version 3.
- Historical document rows/files remain immutable and the current pointer is moved atomically.
- Main implementation: ApplicationDocumentService, ApplicationRevisionWorkflowService, and
  ApplicantRevisionCertificationWorkflowTest.

2.7 Generated certificate content and personalized certificates
---------------------------------------------------------------

- Application creation now collects one recipient name at a time, displays an editable list,
  supports Remove, and validates 1-30 distinct names with a Unicode-aware name format.
- Recipients are persisted per application with deterministic ordering and case-normalized
  uniqueness. Existing applications are safely backfilled with the applicant name.
- Certificate generation creates one Certificate and one PDF per recipient. The first retains the
  application code; additional certificates use -M02, -M03, etc. Applicant claim processes all
  personalized certificates atomically and the UI lists each View/Download action.
- Generated PDFs quote the research title, exclude Payment Proof, and put the reviewed-document
  list after the requested sentence line break.
- The generator uses the configured QR image at fixed 22 mm by 22 mm coordinates and verifies its
  stored hash. Recipient name, validity, signatory, signature hash, QR path/hash/dimensions, and
  background/version provenance are persisted on certificate/version records as applicable.
- Automated PDF text extraction passed for title quoting, line content, and Payment Proof exclusion.
- Main implementation: ApplicationCertificateRecipient, ResearchApplication relationships,
  ApplicationInformationService, ResearchApplicationDraftService, form.blade.php,
  CertificateReleaseService, ApplicantCertificateService, CertificationEligibilityService,
  OfficialCertificateGenerationService, revision-certificates.blade.php, factory, and certificate
  workflow tests.

11. IMPORTANT TECHNICAL DECISIONS
=================================

- Preserve legacy Reviewer role/classification schema for historical compatibility, but exclude it from
  current entitlement, eligibility, forms, filters, and current display.
- Use Adviser role plus reviewer_enabled/reviewer_capacity as the current Reviewer contract.
- Define the disallowed Reviewer for a specific application by actual endorsement credentials/record, not
  simply application.adviser_user_id. This matches the explicit prompt wording and supports Adviser review
  of other Advisers' applications.
- Keep document business versions separate from revision-cycle count. Increment only when an already reviewed
  document is actually replaced; replacing the same revision upload before submit does not increment.
- Keep worksheet immutable submission/artifact history, but a separate business cycle version still must be
  implemented as described in 3.2.
- Use soft deletes on Laravel database notifications with ownership-scoped queries and force-delete only in Bin.
- Store active certificate configuration on the authorized RES Lead and snapshot applicable values/provenance on
  CertificateVersion. Private QR/signature paths are hash-verified before use.
- Use a normalized application recipient table and one Certificate row per recipient rather than one PDF bundle.
- Claim all personalized certificates for one application atomically after one authorized survey response.
- Use blank academic_term_id to mean All; selected IDs are validated against active academic_terms and filtered
  in SQL without broadening role scope.
- Keep preview/download same-origin and private; never move artifacts into public storage or third-party viewers.
- Tests must explicitly set DB_CONNECTION=sqlite and DB_DATABASE=:memory: to avoid local MySQL.
